Implementation Notes

This file is the plain-English log of what changed, what is intentionally different from the original behavior, and what still needs your confirmation. I am keeping it short on purpose so it is useful during handoff.

What is working now

  • The Vercel demo API can reach the backend graph. I confirmed the production URL returns backend-backed global nodes.
  • Completed demo conversations now create scoped graph memories instead of relying only on the browser fallback store.
  • Private notes are filtered by user email. Shared notes are filtered by company/org, so cross-app visibility works without widening private memory.
  • The UI now makes backend-vs-fallback status visible, which makes persistence problems easier to spot.
  • Graph dragging now keeps hot-path node positions in refs and writes DOM positions directly, then commits to React state only when the drag ends.
  • The LLM JSON parser now tolerates common model formatting mistakes, including fenced JSON and invalid escaped backticks, without breaking the extraction pipeline.

Design decisions

  • I treated "visible from a different app" as a hard requirement. Anything that only worked in local browser memory was not enough.
  • I made missing identity fail closed. If a graph request does not include the needed email or company, it should return nothing rather than risk showing the wrong memory.
  • I allowed GTM/company decisions to become shared memory. Personal preferences, taste, and design steering stay private.
  • I kept the simple synchronous completion path for now so behavior stays deterministic while we fix correctness.
  • I kept LLM parser recovery narrow: it repairs invalid escape characters but does not try to guess missing keys or rewrite malformed business content.
  • Node drag updates use left/top because this graph already uses CSS transforms for centering, hover, and entry animation. This keeps the same visual behavior while avoiding per-pixel React renders.

Intentional deviations

  • The frontend fallback no longer invents global notes from raw conversation text. That looked helpful, but it could make private content appear shared.
  • The Slack bot has been moved away from its older hardcoded test_user pipeline and onto the same scoped graph write path used by the Vercel demo.
  • I am not treating Slack MCP as the production recorder. Slack MCP is useful for checking channels/messages from this Codex session, but slash commands need the Slack app/bot service.

Tradeoffs

  • Keeping a fallback store makes local demos resilient, but it can hide real backend failures. The UI now labels the source so this is less confusing.
  • Fail-closed graph reads are safer, but they require the Vercel profile and Slack company/email identity to match.
  • Background processing would reduce perceived latency, but it is a bigger architecture change. I left that as a next step rather than mixing it into this fix pass.
  • During drag, SVG edge lines and labels are also updated through refs. This avoids recalculating and re-rendering every edge on every pointer event.

Slack status

  • A Slack implementation exists in core/slack_bot.py, local Slack secrets are present, and the code now writes via scoped Orange memory requests.
  • The Railway API service can start the Slack Socket Mode bot in the background when ENABLE_SLACK_BOT=true. This keeps the existing API healthcheck available.
  • For Slack-created notes to show in Vercel, the Slack user email should resolve to the same email used in the Vercel profile, such as ranaharshraj3@gmail.com. The current bot token does not expose email yet, so we need the Slack users:read.email scope or ORANGE_SLACK_DEFAULT_USER_EMAIL.
  • The Slack app also needs slash commands for /orange, /orange-stop, and optionally /orange-status.

What I need confirmed

  • Which company name should Slack global notes use? The Vercel graph only shows global nodes when the company/org matches.
  • Should the Slack bot run as a separate Railway service? That is the cleanest production setup for Socket Mode.
  • Please confirm whether to add Slack users:read.email scope or use ORANGE_SLACK_DEFAULT_USER_EMAIL=ranaharshraj3@gmail.com for the first production Slack recorder.
